# 프로젝트 구조

KBO 배경의 야구선수 커리어 시뮬레이션. **게임 로직은 React를 전혀 모르는 순수 TypeScript**이고,
UI는 그 위에 얹힌 얇은 층이다. 저장은 `localStorage`뿐이라 서버가 없다.

```
Next.js 16 (App Router · Turbopack) · React 19 · TypeScript · Tailwind v4
PC에서도 모바일과 같은 한 열(460px)로 본다 — 기기마다 다른 게임이 되지 않도록.
```

---

## 한눈에

```
                     ┌──────────────────────────────────────┐
   사용자 입력  ───▶  │  advance(state, action) → state'     │  ← 순수 함수. 부수효과 없음
                     │          src/lib/career.ts           │
                     └───────────────┬──────────────────────┘
                                     │ 호출
        ┌────────────┬───────────────┼───────────────┬────────────┐
        ▼            ▼               ▼               ▼            ▼
    player.ts     sim.ts        national.ts    postseason.ts  records.ts
    성장·훈련     경기 계산       국제대회·병역     가을야구      목표·대기록
        │            │               │               │            │
        └────────────┴───────┬───────┴───────────────┴────────────┘
                             ▼
                          rng.ts  (mulberry32 · 시드가 세이브에 들어간다)

                     ┌──────────────────────────────────────┐
   화면  ◀────────── │  storage.ts (localStorage)           │
                     │    └ migrate.ts — 구버전 세이브 흡수   │
                     └──────────────────────────────────────┘
```

**핵심 규칙 하나**: 게임 상태는 `GameState` 한 덩어리이고, 그것을 바꾸는 유일한 통로가
`advance(state, action)`이다. UI는 액션을 던지고 새 상태를 받아 그리기만 한다.
난수 시드가 상태 안에 있어서 **같은 세이브 + 같은 액션이면 언제나 같은 결과**가 나온다.
스크립트로 수천 개 커리어를 돌려 밸런스를 측정할 수 있는 것도 이 구조 덕분이다.

## 시즌 한 바퀴

```
고교 3학년 → 진로(드래프트 / 대학 2년) → 신인 드래프트
  ┌───────────────────────── 매 시즌 ─────────────────────────┐
  │ [입영 통지] → 스프링캠프(강도 × 방향) → [대표팀 발탁]        │
  │   → [WBC 3월] → 전반기(월별)                               │
  │   → 올스타 브레이크 [올스타 선정 → 올스타전] [올림픽 7월]     │
  │   → 후반기(월별) [아시안게임 9월]                           │
  │   → 가을야구 [프리미어12 11월] → 시즌 총평                   │
  │   → [커리어 갈림길] → 연봉협상 or FA → 스토브리그(이적·상무)  │
  └──────────────────────────────────────────────────────────┘
      → [은퇴 권고(거부 가능)] → 은퇴 → 진로 선택 → 명예의 전당 투표
```

- 전반기·후반기는 **월 단위로 따로** 시뮬레이션하고, 월말마다 콜업·강등을 판정한다.
- 국제대회는 대회마다 실제 개최 월이 달라 `Tournament.slot`(PRE/MID/LATE/POST)에 따라
  네 시점 중 하나에서 치러지고, **리그 일정과 분리된 전용 중계**로 보여준다.
- 전역하는 해는 스프링캠프와 전반기를 건너뛰고 **올스타 시점에 합류**한다.

## 시뮬레이션이 도는 방식

경기를 한 판씩 돌리지 않는다. **한 구간(한 달·한 시리즈·한 경기)을 확률로 한 번에** 계산한다.

```
능력치 ──▶ 비율 지표 ──▶ 카운팅 스탯 ──▶ WAR
```

| | 유도하는 비율 | WAR |
|---|---|---|
| 타자 | `BB% · K% · BABIP · 타구당 홈런율` | wOBA → wRAA + 수비 런 + 포지션 조정 |
| 투수 | `K/9 · BB/9 · HR/9 · BABIP` | FIP → RA9 대비 대체 수준 |

두 가지 장치가 기록을 현실적으로 만든다.

- **누적 차분 배분** — 월별로 따로 반올림하면 시즌 합계가 144경기와 어긋난다.
  `SimInput.cume: [from, to]`로 넘겨 누적값의 차이로 배분한다.
- **소표본 추첨** — 한 경기 4타석에 기댓값을 반올림하면 언제나 같은 결과(`.250`)가 나온다.
  `pa < 60` / `ip < 25` 구간은 반올림 대신 실제로 추첨한다.

## `scripts/` — 측정 도구

밸런스를 눈대중으로 고치지 않기 위한 장치다. 번들에는 들어가지 않는다.

```bash
npx tsx scripts/audit.ts      # ★ 288개 커리어 전 경로 스트레스 테스트 (필수)
```

`audit.ts`는 모든 진로·병역·협상·이적 조합을 돌려 **예외 0 · 무한정지 0 · 이상값 0 ·
전 단계 도달**을 확인한다. 어떤 변경 후에도 이걸 돌린다.

나머지는 목적별로 나뉜다.

| 분류 | 스크립트 |
|---|---|
| 성장·능력 | `balance` `potcap` `aging` `devrate` `training` `hellcheck` `styles` |
| 진입·데뷔 | `draft` `draftscore` `debut` `rookieyear` `rookiestat` `amateur` |
| 시즌·기록 | `statdist` `games` `totals` `war` `park` `awards` `titles` `goals` `allstar` |
| 커리어 운영 | `salary` `nego` `fa` `transfer` `transferodds` `transfersweep` `roles` `roster` |
| 병역·국제 | `service` `sangmu` `national` `intlline` |
| 시스템 | `systems` `features` `notices` `textcheck` `legacy` `migration` `check` |

`autoplay.ts`는 나머지 스크립트가 공유하는 자동 플레이 엔진이다.
**새 phase·action을 만들면 `autoplay.ts`와 `audit.ts`의 switch에 반드시 추가한다.**
안 하면 `default: RETIRE`로 빠져 측정값이 전부 거짓이 된다.

## 세이브

`GameState` 하나가 세이브 하나다. `localStorage`에 `slb:games` 키로 전부 들어간다.

```
localStorage ──▶ migrate.ts ──▶ GameState[]  ──▶ useSyncExternalStore ──▶ 화면
                 (저장소 경계에서 한 번)
```

`GameState`에 필드를 추가하면 **반드시 `migrate.ts`에 기본값을 넣는다.**
저장소 경계에서 한 번 통과시키므로 여기만 지키면 구버전 세이브가 산다.
구단 재편처럼 id가 바뀌는 변경도 여기서 흡수한다(`TEAM_ID_ALIAS`).
